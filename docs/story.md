## 完整版

### 同一个词，你付了三次钱

晚上十一点，你在读一篇讲检索增强的文档。第三段，一个缩写挡住了你：HNSW。

你切开浏览器，搜索，读了两篇博客，懂了——分层图、粗跳细找、拿一点准确率
换一百倍速度。你切回文档，继续往下读。十分钟后，HNSW 又出现了。你盯着它
看了三秒：刚才……查了什么来着？

于是你又搜了一遍。

这不是记性的问题，是工具形状的问题。搜索引擎和聊天窗口都是为"一次一问"
设计的：你问，它答，然后你们的缘分就尽了。它不记得你问过 HNSW，更不记得
你上周问过 RAG、上上周问过向量数据库——这三个词本来是亲戚，但你从来没有
机会把它们放在同一页纸上。每一次查询都是一次性的，什么也攒不下来。

而在所有老式的学习工具里，其实早有人解决了这个问题：生词本。查过一次，
抄下来，下次遇见，翻一眼。生词本的问题只有一个——它只认识词典里有的词。
你让它查 HNSW、QUIC、MCP，它只会沉默。

gloss 就是给生词本换上一颗大模型的心脏。

复制一个词，敲一下 `gp`：一张中文卡片立在那里——一句话定义、三句人话解释、
和它相关的概念。这张卡存在你自己的电脑里，从此这个词你只查这一次。下次
遇见，它秒回，不花一分钱。而你收录的词会自己认亲：查"队头阻塞"的那天，
gloss 会告诉你，它和你两周前收录的 QUIC 是同一件事的两面。

三个月后，`gloss related RAG` 会给你看一张网。那张网不是知识图谱产品画给
你看的，是你的阅读自己长出来的。

**查一次，永久拥有。**

## 压缩版（README Why 用）

> 问三次聊天机器人"HNSW 是什么"，你付三次钱，答案蒸发三次。真正贵重的
> 步骤不是"问"，而是"留住"。生词本早就发明了留住的方法——只是它不认识
> 词典之外的技术词。gloss 给生词本换上大模型的心脏：查询先走本地缓存，
> 未命中才调一次模型，此后终身免费；收录的概念自动互相链接，你的词库会
> 长成一张只有你拥有的网。

## 一句话版

- 查一次，永久拥有。（现有 tagline）
- 给生词本换上大模型的心脏。
- 你查过的每个词，都不该只活在一个聊天窗口里。

## 附：故事 → 产品的映射（决策档案）

| 故事节拍 | 产品要求 | 状态 |
|---|---|---|
| "又搜了一遍"的懊恼 | 命中必须是"领回来" | ✅ ⚡ cache hit |
| "缘分尽了" | 问完要能留住 | ✅ 卡片 |
| "生词本只认识词典里的词" | LLM 驱动 | ✅ |
| "三个词是亲戚" | 概念自动认亲 | ✅ 链接+回填 |
| "存在你自己的电脑里" | 本地优先 | ✅ SQLite |
| "刚才查了什么来着" | 主动让你再看见 | ❌ quiz 待做 |
| "它告诉你两个词的关系" | 关联要被"讲述" | ⚠️ review 只列不说 |
| "深夜/任何地方" | 移动端 | ❌ 待做 |
| "三个月后" | 多设备延续 | ❌ 同步待做 |

三条硬结论：①故事高潮在第三幕（回头看），产品最强在第一幕（收录）→ quiz 是兑现故事；②关联要被讲述，不只是存着；③同步与移动端是故事成立的地基。
